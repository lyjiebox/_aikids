## 附：验收流程

1. **自测阶段**：开发完成自测后逐一打勾
2. **交叉验收**：开发与 PM 交叉逐一验收
3. **回归验收**：修复 BUG 后回归受影响用例
4. **签收标准**：所有 P0 和 P1 用例通过，P2 用例 >= 90% 通过

### 优先级定义

| 级别 | 定义 | 是否阻塞发布 |
|------|------|-------------|
| P0 | 核心流程崩溃、数据丢失、安全漏洞 | ❗ 必须修复 |
| P1 | 主要功能不正常、严重体验问题 | ❗ 必须修复 |
| P2 | 非核心功能问题、轻度体验问题 | 可协商 |
| P3 | 视觉细节、文字错误 | 可后续迭代 |

### UAT 通过标准

- ✅ P0 用例通过率：100%
- ✅ P1 用例通过率：100%
- ✅ P2 用例通过率：>= 90%
- ✅ 无已知严重 BUG（P0/P1）
- ✅ 所有验收项已标记状态（✅ / ❌ / ⬜）
