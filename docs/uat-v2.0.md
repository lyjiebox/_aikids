## 附：验收流程与通过标准

### 验收流程

1. **自动化检查**：`npm run build`、Remix 相关组件/字段存在性检查
2. **开发自测**：按本节 P0 用例逐项打勾
3. **交叉验收**：开发完成后浏览器手工执行第 3–8 节
4. **报告输出**：结果写入 `temp/v2.0/uat-test-report-YYYY-MM-DD.md`
5. **回归验收**：BUG 修复后重测受影响用例

### 优先级定义

| 级别 | 定义 | 是否阻塞 V2.0 发布 |
|------|------|-------------------|
| P0 | Remix 主流程、数据记录、空指令拦截 | 必须 100% 通过 |
| P1 | 来源展示、旧数据兼容、异常处理、AI 质量 | 必须 100% 通过 |
| P2 | 视觉细节、超长指令、Mock 边缘场景 | >= 90% 通过 |

### V2.0 UAT 通过标准

- P0 用例通过率：**100%**
- P1 用例通过率：**100%**
- P2 用例通过率：**>= 90%**
- 无未关闭的 P0/P1 级 BUG
- 验收报告已存入 `temp/v2.0/`
- 以下 scope 外项不阻塞发布（见 design §1.1）：
  - Remix 链条查看 UI
  - Gallery 卡片 Remix 按钮
  - 「被改编了 N 次」展示
  - 社区广场按 remixCount 排序
