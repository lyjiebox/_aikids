# Proposal: AI 儿童创意游戏平台（AI Kid Games）

## 文档规范

本项目所有正式文档统一存放在项目根目录下的 `docs/` 目录内。

文档存放规则：
- `proposal.md`、`design`、`uat` 以及未来新生成的正式文档，均必须放在 `docs/` 目录内。
- `design`、`uat` 及后续文档如果仅用于特定版本，文件名必须包含版本号。
  - 示例：`design-v1.0.md`
  - 示例：`uat-v1.0.md`
- 仅用于特定版本的文档，其文件内容标题与正文也必须明确包含版本号。
- 项目根目录下必须创建 `temp/` 子目录。
- 项目过程中产生的各种临时文件，包括临时代码、测试报告、调试输出、实验文件等，均必须放在 `temp/` 目录内。
- `temp/` 内临时文件必须按版本号划分子目录。
  - 示例：`temp/v1.0/`

## Why（背景和目标）

### 市场背景

当前 AI 互动内容赛道（Aippy、Loopit 等）聚焦于 15-25 岁欧美 Gen Z 用户，以 AI 生成小游戏 + UGC 社区为核心模式。国内市场在 **3-10 岁儿童 + AI 创意游戏** 方向几乎空白——少儿编程产品（编程猫、核桃编程）偏「教编程」而非「用 AI 创作」，且面向 6 岁以上儿童。

### 用户痛点

- **家长焦虑**：AI 时代来临，不知如何让孩子安全、有效地接触和了解 AI
- **儿童需求**：3-10 岁孩子有强烈的表达欲和创造欲，但缺乏适合年龄的创作工具
- **教培机构痛点**：传统画画/乐高/STEM 机构缺乏 AI 特色课程，难以差异化竞争

### 项目目标

构建一个面向中国 3-10 岁儿童的 AI 创意游戏平台，让孩子通过**语音输入**让 AI 生成可交互小游戏，培养对 AI 的兴趣和基础认知。通过**线下地推**进入幼儿园和教培机构，以 **B 端 SaaS + C 端课程**实现商业化。

## How（开发方式）

本项目采用 AI-Native 开发方式：
1. 由我制定项目企划书 `docs/proposal.md`
2. AI 根据企划书生成带版本号的 Design 和 UAT 文档，例如：
   - `docs/design-v1.0.md`
   - `docs/uat-v1.0.md`
3. 我确认 Design 和 UAT 后，AI 自行完成：**开发 → 测试 → 修复 → 测试 → 验收通过** 的全流程
4. 在必要的决策环节，AI 需向我确认后再继续
5. 开发过程中的临时文件、测试报告、实验代码等，必须放入对应版本的 `temp/` 子目录，例如 `temp/v1.0/`

## Who（用户故事）

- 作为 3-10 岁的儿童，我希望对着手机说出我的想法（如"我想做一个打地鼠游戏，地鼠是小兔子"），AI 就能帮我生成一个可以玩的小游戏，让我体验创造的乐趣。
- 作为家长，我希望有一个安全的平台让孩子接触 AI，能控制使用时长，看到孩子的创作成果，了解孩子的兴趣发展。
- 作为幼儿园/教培机构的老师，我希望有一个 AI 启蒙教学工具，能批量管理学生账号、分发创作任务、查看学生作品，提升机构的科技特色竞争力。

实现MVP，达到能用的效果。

- [x] 独立后端 API 服务（AI 生成、作品管理），双模式：Vercel Serverless（`api/`）+ 本地开发（`server/`）
- [x] 首页：面向儿童的简洁入口，大图标 + 语音引导

- [x] 游戏模板库：预设 5-10 个主题模板（动物、汽车、公主、恐龙、太空等），降低创作门槛
- [x] AI 游戏生成：调用大模型 API，根据儿童语音描述生成简单可交互的 HTML5 游戏
- [x] 游戏播放器：在 App 内运行 AI 生成的游戏（H5 用 iframe 沙箱）
- [x] 作品列表页：展示该设备上生成过的游戏作品，支持回放和删除

- [x] PC 和手机 Web 端均可运行，响应式适配（极简版）

3. 虽然设置了5分钟等待时间，但太复杂的游戏，返回失败率偏高

## 技术约束

### 前端

- 框架：Vite + React 18（JavaScript + 少量 TypeScript）
- 路由：React Router v6（BrowserRouter）
- 样式：普通 CSS 文件，明亮、多彩、圆角、大字体，适合儿童审美
- 目标平台：V1.x → H5（PC + 手机 Web）；V2.x → 微信小程序
- 构建工具：Vite
- 部署：Vercel（静态站点 + Serverless Functions）

### 后端

- 运行时：Node.js
- 框架：Hono（轻量，支持 Vercel Functions / 本地 Node.js 服务）
- 语言：TypeScript（严格模式）
- AI 生成：调用火山引擎 Responses API（支持 Seed 2.0 Pro、DeepSeek、GLM 等模型）
- 语音识别：V1.0 浏览器 Web Speech API；V1.1 起迁移到后端语音识别服务
- 存储：V1.0 前端 localStorage；V1.1 起迁移到云存储
- 部署：Vercel Functions（生产环境 `api/` 目录）+ 本地 `server/` 开发服务

### 架构原则

- **前后端分离**：前端只做 UI 和交互，核心逻辑（AI 生成、语音识别、内容审核）全部在后端
- **一套 API，多端复用**：V1 H5 和 V2 小程序调用同一套后端 API
- **渐进增强**：V1.0 最小可用，V1.1 补云端能力，V2.0 扩展小程序
- **双后端模式**：Vercel 部署用 `api/generate.ts`（Serverless），本地开发用 `server/`（独立 Hono 服务）

## 设计原则

- **儿童优先**：所有交互必须适合 3-10 岁儿童，大按钮、少文字、多彩色
- **安全第一**：AI 生成内容必须在沙箱中运行，Prompt 必须过滤不当内容
- **语音为主**：核心创作流程以语音交互为主，文字输入为辅助
- **即时反馈**：AI 生成过程需要有趣的加载动画，降低等待焦虑
- **家长可控**：所有设置和敏感操作需家长验证
- **跨端复用**：Taro 组件和业务逻辑最大化复用，平台差异最小化隔离
