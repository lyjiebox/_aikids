## 1. 测试环境

### 1.1 软件环境

| 项目 | 版本 |
|------|------|
| Node.js | >= 18（本地验证使用 v24） |
| 浏览器 | Chrome / Edge 最新稳定版、Safari 最新版 |
| 前端 | Vite + React 18 |
| 后端 | Hono（本地 `server/` 与 Vercel `api/` 双模式） |
| 测试桩 | `temp/v3.2/stub-model-server.mjs`（Node 原生 HTTP，模拟 OpenAI 兼容接口） |

### 1.2 测试前置

#### 1.2.1 启动模型测试桩

```bash
node temp/v3.2/stub-model-server.mjs
# 监听 http://localhost:4999
```

测试桩支持的模型标识：

| `model` 值 | 行为 |
|-----------|------|
| `stub-model` | 正常返回：测试请求返回 `OK`；生成请求返回一个可解析的 JSON 游戏 |
| `force-401` | 返回 HTTP 401 |
| `force-500` | 返回 HTTP 500 |
| `force-empty` | 返回 HTTP 200 但内容为空 |
| `force-timeout` | 延迟 10 秒后返回（用于超时测试） |
| `markdown-game` | 生成请求返回 Markdown 代码块包裹的 JSON（解析回归） |
| `plain-html` | 生成请求返回纯 HTML（解析回归） |
| `truncated-json` | 生成请求返回截断 JSON（解析回归） |

#### 1.2.2 启动本地后端（指向测试桩）

```bash
cd server
VOLCENGINE_API_KEY=test-key \
VOLCENGINE_BASE_URL=http://localhost:4999/v1/chat/completions \
DOUBAO_ENDPOINT_ID=ep-doubao-uat \
DEEPSEEK_ENDPOINT_ID=ep-deepseek-uat \
GAME_MODEL=deepseek \
ALLOW_LOCAL_MODEL_HOSTS=1 \
MODEL_TEST_TIMEOUT_MS=2000 \
npm run dev
# 监听 http://localhost:4000
```

#### 1.2.3 启动前端

```bash
npm run dev
# 默认 http://localhost:3000
```

#### 1.2.4 测试产物

- 测试报告、调试输出、测试桩、临时脚本必须放在 `temp/v3.2/`
- 报告命名：`uat-test-report-YYYY-MM-DD.md`

#### 1.2.5 自动化脚本

| 脚本 | 用途 |
|------|------|
| `temp/v3.2/stub-model-server.mjs` | OpenAI 兼容测试桩（成功/401/500/空/超时/重定向/解析变体） |
| `temp/v3.2/api-uat.mjs` | 本地 `server/` API 自动化验收（模型清单、测试、生成、安全、解析） |
| `temp/v3.2/api-vercel-uat.mjs` | Vercel `api/` 对等验收（esbuild 产物直接调用） |
| `temp/v3.2/model-utils.test.mjs` | 前端模型工具函数单元测试（校验/选择/请求参数） |
| `temp/v3.2/storage.test.mjs` | localStorage 容错测试（损坏 JSON/非法条目/去重/上限） |
| `temp/v3.2/ssr-smoke.mjs` | 页面 SSR 冒烟测试（导入、Hooks、路由上下文） |
| `temp/v3.2/ui-cdp-uat.mjs` | Chrome CDP UI 自动化（首页选择、生成、模型配置增删改测） |
| `temp/v3.2/ui-extra-uat.mjs` | 补充 UI 验收（新标签页、移动端、旧作品兼容） |

### 1.3 固定测试数据

| 字段 | 值 |
|------|-----|
| 自定义模型名称 | `测试桩模型` |
| 接口地址 | `http://localhost:4999/v1/chat/completions` |
| 模型 ID | `stub-model` |
| API Key | `test-key` |
| 环境默认模型 | `deepseek`（DeepSeek V4 Pro） |

## 附：验收流程与通过标准

### 验收流程

1. **静态检查**：确认文档、文件、路由、环境变量示例。
2. **构建验证**：`npm run build`、`cd server && npm run build`、esbuild 打包 Vercel API。
3. **启动测试桩 + 后端 + 前端**。
4. **API 自动化**：按第 5 节逐项执行 curl/脚本，结果写入 `temp/v3.2/uat-test-report-YYYY-MM-DD.md`。
5. **浏览器手工**：按第 6-9 节执行，记录截图或文字结果。
6. **回归**：按第 8 节抽查。
7. **修复-复测**：失败项修复后重新执行对应用例，直到满足通过标准。

### 优先级定义

| 级别 | 定义 | 是否阻塞 V3.2 发布 |
|------|------|-------------------|
| P0 | 模型选择、环境变量兜底、增删改查、测试、构建、安全底线 | 必须 100% 通过 |
| P1 | 持久化、兼容、异常处理、移动端、回归 | 必须 100% 通过 |
| P2 | 视觉细节、极端边界、性能 | >= 90% 通过 |

### V3.2 UAT 通过标准

- P0 用例通过率：**100%**
- P1 用例通过率：**100%**
- P2 用例通过率：**>= 90%**
- 无未关闭的 P0/P1 级 BUG
- 验收报告已存入 `temp/v3.2/`
- 不在 V3.2 范围（不阻塞发布）：
  - 服务端模型持久化 / 多设备同步
  - 多模型 A/B 自动优选
  - 模型用量/配额统计
